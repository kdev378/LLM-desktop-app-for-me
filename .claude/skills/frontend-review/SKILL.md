# Frontend Review

## 入力

利用者の目的と流れ、対象画面または実装、対象端末、プロジェクトの様式や参考デザイン、`context/personal/ui.md`、`context/generic/frontend.md`。

## 手順

1. プロジェクトで明示された選択を抜き出す。`context/personal/ui.md` の「未定」項目は未定のままにする。
2. 主要な流れに加え、エラー、読み込み中、空、復帰、破壊的操作の流れを一通り歩く。
3. 視覚的な階層、操作の分かりやすさ、情報密度、ナビゲーション、レスポンシブ、アクセシビリティ、動き、フォーム、エラー、設定、状態表示を点検する。
4. 客観的な不具合 / generic の既定に基づく推奨 / プロジェクト固有の主観的判断を分けて書く。
5. 実装するときは、既定を戻せるようにし、不要な設定を増やさない。
6. 現実的な範囲で、画面幅、キーボード、拡大、コントラスト、各状態を確認する。

## 出力

対象範囲 / 影響の大きい順の指摘 / オーナーの好みとの整合 / 未指定のまま決めた事項 / 実装した変更 / 確認結果。

## うまくいかないとき

プロジェクトの美的方針が不明なとき、「オーナーの好みに合っている」と主張しない。抑制した一般的な既定を当て、方向性は暫定と明記して、参考例を求める。
