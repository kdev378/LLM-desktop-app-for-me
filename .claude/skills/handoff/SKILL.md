# Handoff

## 入力

当初の目的、リポジトリの状態、変更と判断、検証結果、既知の障害とリスク。

## 手順

1. 結果を完了条件と、明示された除外事項に照らす。
2. 利用者から見た成果と、実際に触った範囲をまとめる。
3. 影響の続く構造・インターフェースの判断を、プロジェクトの記録先に残す。
4. 実行した検証コマンドと結果を並べ、実行していない検査を区別する。
5. 移行、巻き戻し、運用、制限、先送りした範囲外の項目を書く。
6. `context/lifecycle/README.md` の発火条件を満たす出来事があった場合だけ、`context/lifecycle/log.md` に気付きを追記する。

## 出力

- 何ができるようになったか（オーナー向け、平易な言葉で先頭に）
- 自分で確かめる手順: 起動方法、試す操作、期待される結果
- 変更した挙動と成果物
- 影響の大きい判断とその理由
- 検証したこと・していないこと
- 運用と移行の注意
- 未完了、既知の不具合、障害

## うまくいかないとき

途中で止めるときは、最後に正常だった状態と、安全に再開できる地点を書く。未完了・未検証の挙動を完了として書かない。
