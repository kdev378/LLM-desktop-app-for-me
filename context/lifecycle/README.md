# Lifecycle

このルール集そのものを育てるための記録。作業のたびに書くものではない。

## いつ書くか

次のどれかが起きたときだけ `log.md` に追記する。

- 出来上がったものに、はっきり不満があった。
- エージェントが同じ種類の誤解や失敗を、2回以上した。
- 明文化されていなかったオーナーの好みが、やり取りの中ではっきりした。
- ルールどうしが矛盾した、またはルールが実態に合わなかった。

一度きりのプロジェクト固有の事情は書かない。それは Project Context に属する。

## いつルールへ昇格させるか

記録が**繰り返された**か、**影響が大きい**か、**安定したオーナーの好みを示している**とき。
1件の出来事を、そのまま普遍的なルールにしない。

## 昇格の手順

1. `log.md` の記録を読み返し、同種のものがあるか確かめる。
2. Generic（誰にでも当てはまる）か Personal（オーナー固有）かを決める。
3. 該当する正本ファイル1つを更新する。複製しない。
4. `log.md` の末尾に、変更したファイルと内容を1行で追記する。
