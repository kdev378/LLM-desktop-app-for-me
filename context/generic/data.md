# Data and Migration

保存形式・移行を扱うときに読む。

- `MUST` 永続化の設計前に、正本データ、派生データ、所有者、寿命、保持期間、復旧の期待値を特定する。
- `MUST` 取り込み時、および不可逆な表現変更の前に検証する。
- `SHOULD` 将来の読み手が表現を区別する必要があるなら、スキーマや形式にバージョンを持たせる。
- `MUST` 移行は、中断、部分失敗、再試行、巻き戻しまたは前進復旧を想定して設計する。
- `SHOULD` 再実行があり得るなら移行を冪等にする。できないなら、実行済み・部分実行を明示的に検出する。
- `MUST` 再生成できないデータは、危険な移行の前に保全・バックアップし、結果を検証してから旧表現を消す。
- `DO NOT` 移行を成功に見せるために、未知・不正・古いデータを黙って捨てる。隔離するか、報告するか、方針として文書化する。
- `MUST` 大きさ、文字コード、順序、過去形式の差異が正しさに影響し得るなら、実運用に近い量と端の事例で試す。
- `SHOULD` 危険が下がるなら、スキーマ変更・データ移送・挙動の切り替え・後片付けを段階に分ける。
- `SHOULD` 選定時は安定性、可搬性、堅牢性を優先する。それを損なわない範囲で、手で読み書きできる形式を選ぶ。
