# Security and Compliance

認証、秘密情報、個人データ、配布物を扱うときに読む。

## セキュリティ

- `MUST` 保護された操作ごとにサーバー側で認可を検証する。認証だけでは不十分。
- `MUST` 確立された暗号・認証ライブラリを使う。暗号方式、パスワード保存、セッション方式、秘密の形式を自作しない。
- `MUST` 秘密の露出、権限、保持データ、機微なログを最小化する。出力から資格情報とトークンを伏せる。
- `MUST` 信頼できないデータを、宛先に応じて検証・エスケープする。DBはパラメータ化、プロセス起動は安全な呼び出しを使う。
- `MUST` 破壊的操作は範囲を限定し、対話的なら確認を挟み、現実的な範囲で復旧可能にする。危険なデータ変換の前にバックアップか巻き戻し手段を用意する。
- `SHOULD` 露出と影響に見合う脅威だけを想定する。複雑さだけ増えて危険が減らない対策を避ける。
- `MUST` セキュリティやデータ喪失に関する仮定を検証できないときは、止めて表明する。

## ライセンスと配布

- `MUST` 配布前に、依存関係、流用コード、フォント、素材、データセット、モデル、生成物のライセンスと利用条件を確認する。
- `MUST` 想定する利用、改変、配布、ホスティング、商用可否が条件と適合するか検証する。
- `SHOULD` パッケージのメタデータや第三者の要約より、ライセンス本文と提供元の条件を根拠にする。
- `MUST` 必要な著作権表示、帰属、ライセンス本文、ソース提供、改変の開示を保つ。
- `DO NOT` 公開されていることを、自由に使える根拠と見なす。
- `MUST` 出所が不明、またはライセンスが非互換なものは、解決するまで配布の阻害要因として扱う。
