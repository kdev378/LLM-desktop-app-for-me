# Documentation

ドキュメントを書くときに読む。

- `MUST` 使う・運用する・診断する・安全に変更するために必要な情報を書く。自明なコードの説明は書かない。
- `MUST` 導入または起動から、最初に成功するまでの短い道筋を先頭に置く。
- `MUST` 利用者から見える設定の一覧を、既定値、有効な値、効果、関連するリスクとともに示す。
- `SHOULD` 各ルール・事実の正本を一箇所に置き、複製ではなく参照でつなぐ。
- `MUST` インターフェース、導入手順、挙動、設定、移行、運用手順が変わったらドキュメントを更新する。
- `SHOULD` 影響の続く決定を短く記録する。背景、選んだ案、他の候補、結果、戻し方。
- `MUST` コマンド、実例、置き換え箇所、期待される出力、警告、破壊的な手順を区別できるように書く。
- `SHOULD` 見出しを安定させ、用語を明示し、エラー識別子を検索可能にし、手順を単体で完結させる。LLMが該当箇所だけ取り出して、そのまま手順を組めることを想定する。
- `AVOID` 運用上の重要な事実を、散文、スクリーンショット、リリース告知の中だけに置くこと。
- `AVOID` テストや実装が裏付けていない挙動の約束。
