# Frontend Defaults

画面を作る・直すときに読む。見た目と操作感の好みは `personal/ui.md` が正本。ここは分野を問わない既定。

## 基本

- `SHOULD` プラットフォーム標準の意味付けと部品を使う。独自部品は、同等の挙動を備えていて、かつ理由がある場合に限る。
- `MUST` 主要な操作を、ポインタの精度、ホバー、色、音、アニメーション、時間制限だけに依存させない。
- `SHOULD` キーボード操作を、論理的な順序と明確なフォーカス表示で支える。
- `MUST` 対話要素に、プログラムから読める名前、ラベル、役割、状態、関係を与える。
- `MUST` 読みやすいコントラストを保ち、意味や状態を色以外でも示す。
- `SHOULD` 文字の拡大、ズーム、翻訳、内容の増加に耐える。
- `SHOULD` 「視差効果を減らす」等のシステム設定を尊重する。

## 状態とエラー

- `MUST` 検証エラーを該当する入力欄に結び付ける。複数あるならまとめも出す。
- `MUST` エラーは、簡潔な原因と実行可能な対処を最初に出す。詳細は展開して見られるようにし、秘密や不要な個人情報は出さない。
- `MUST` 未解決の失敗通知を自動的に消さない。
- `MUST` 入力済みのデータを、回復可能なエラーで失わせない。
- `MUST` 長い処理、段階的な処理、失敗し得る処理は、無反応にせず進行中と分かるようにする。
- `MUST` 多重送信や競合が危険な操作は、待機中の再実行を防ぐ。
- `AVOID` 実際の進捗が取れない処理で、正確に見える架空のパーセント表示を出すこと。

## 破壊的操作

- `MUST` 影響範囲と結果を操作前に明示する。
- `SHOULD` 取り消し、ゴミ箱、復元、猶予期間など、回復可能な設計を優先する。
- `SHOULD` 確認の強さを損害の大きさに比例させる。日常的で戻せる操作に過剰な確認を出さない。
