# 埋め込みモデルの比べ方

Akari の内蔵の埋め込みモデルを選ぶための測定（`docs/spec/14-memory.md`「モデルの選び方」）。
このリポジトリ自体（日本語の仕様書と TypeScript のコード）を、Akari と同じ規則で切って索引にし、
`queries.json` の40問で「正解のファイルが上位に出るか」と、CPU での速さ・メモリを測る。

## 動かし方

[uv](https://docs.astral.sh/uv/)（Python の道具をまとめて入れて動かすもの）を使う。入っていなければ:

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh     # または brew install uv
```

このリポジトリの中で:

```sh
git pull
uv run tools/embed-bench/bench.py
```

- 初回は必要な部品（PyTorch など）と、4つのモデルを取得する。合わせて数GB、回線しだいで数分〜十数分
- 測るのは CPU（Akari の内蔵は CPU で動かす前提のため）。速さは機械しだいなので、機械の名前も結果に出る
- 終わると表が出て、`tools/embed-bench/results/<日時>.md` に保存される。**その .md をそのまま貼ってほしい**
- 1つのモデルだけ: `uv run tools/embed-bench/bench.py --models cl-nagoya/ruri-v3-70m`
- 読み込めないモデルがあれば「失敗」の欄に理由が出る。配布元のプログラムを動かさないと読めないモデルなら
  `--trust-remote-code` を付ければ読めるが、そのプログラムの中身は確かめていない（付けるかは任せる）

Linux で PyTorch が GPU 用の大きなもの（数GB）になるのを避けたいときは:
`uv run --index https://download.pytorch.org/whl/cpu tools/embed-bench/bench.py`（未確認）

## 測っているもの

| 項目 | 意味 |
|---|---|
| 1位 / 5位以内 | 正解のファイルが、結果の1位 / 上位5件に入った問いの割合（ファイル単位） |
| MRR@10 | 正解が何位に出たかの逆数の平均（上位10件まで）。1 に近いほどよい |
| 種類ごと | 日本語→文書、日本語→コード、英語→コード、日本語と英語の混在 |
| 索引づくり | 全チャンク（約1,200）を埋め込む時間 |
| 問い1つ | 問いを1つ埋め込む時間（検索のたびにかかる） |
| 最大メモリ | そのモデルを測ったプロセスの最大の使用量 |

「基準: 文字の重なり」は埋め込みを使わない、キーワード検索に近いもの。これに勝てないモデルは使う意味が薄い。

## 注意

- 問題集は私（Claude）が作った40問で、正解はファイル単位。大きい差は信じてよいが、数問の差は誤差の範囲
- モデルごとの「文の前に付ける印」は、モデルが設定に持っていればそれを使う。Ruri だけは説明の記憶から補っている（未確認）。
  実際に使った印は結果の「使った印」に出る
- 対象は `queries.json` に書いた commit の時点のファイル（後で仕様やコードが変わっても、結果がずれないように）
