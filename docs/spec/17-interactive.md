# 17 — 対話画面（`akari`）

引数なしの `akari` で入る、ターミナルの中で動く対話アプリ。Claude Code や Codex の CLI と同じ使い口。
**相談（chat）と作業の依頼（run）を1つの入力欄にまとめる。**

今あるサブコマンド（`run` / `chat` / `-p` / `--json`）は**ヘッドレス**（画面を持たない使い方）として、
挙動を変えずに残す。スクリプトや試験はそちらを使う。

## 起動

```sh
akari                         # 対話画面。カレントが作業フォルダ
akari -C ~/proj               # 作業フォルダを指定
akari -c                      # この作業フォルダの直近の会話の続きから
akari --conversation <ID>     # 指定した会話の続きから
akari -m <モデル> -e <接続先>
akari --permission auto-edit  # 権限の初期値。画面の中でも変えられる
akari --read-only / --no-tools / --think <量> / --tools-mode <方式> / --no-save
```

- 標準入力か標準出力が端末でないとき（パイプの中など）は、画面を出さずにヘルプを出す（今と同じ）。
- 引数に文字列があれば、今までどおり `run` として1回実行して終わる（`akari "テストを通して"`）。
- 接続先の選択、モデルの選択、道具の渡し方の判定は、`run` と**同じ部品**で行う。
  画面とヘッドレスで違う判断をさせない。

### 作業フォルダにできない場所で起動したとき

ホームフォルダなど、`Workspace.open` が断る場所（05-agent.md「パス境界」）では、
**道具なしの会話**（今の `akari chat` 相当）で起動する。起動時に理由と、道具を使うには
プロジェクトのフォルダで起動し直すことを出す。この状態では `/tools` で道具を有効にできない。
会話は `chat` の会話として保存する（作業フォルダを持たないため）。

## 1回の送信と、記録

- 1回送るごとに **1つの実行**（新しい実行 ID）とする。`run` を何回も `-c` で続けたのと同じ記録になる。
  変更の記録と取り消しも1回ごと（`/undo` は直前の1回の変更を戻す）。
- 会話は既定で保存する。`--no-save` なら保存しない。保存の形式は `run` / `chat` と同じ（04-chat.md・07-data.md）。
- 実行の合間に、モデル・権限・道具の範囲を変えてよい。記録は「何を呼び、何が返ったか」で持ち、
  送るときに組み立て直すので、途中で変えても続きが壊れない（`run -c` で既にそうしている）。

## 画面

```
╭ Akari 0.1.0 ─────────────────────────────────────╮   ← 起動時に1度だけ（流れていく）
│ LM Studio / gemma-4-e4b   ~/myproject            │
│ 権限: 承認する   道具: 8種   会話: 01M6…（新規）  │
╰──────────────────────────────────────────────────╯
› README の typo を直して                              ← 送った入力
  read_file README.md                                  ← 道具の呼び出しと結果
    ✓ README.md を 40 行読んだ
  直しました。…                                        ← モデルの応答
  完了  12.3秒

（ここから下だけが書き換わる）
  ⠋ 生成中 4秒 · Esc で停止                             ← 生成中だけ
╭──────────────────────────────────────────────────╮
│ › 入力                                            │   ← 入力欄
╰──────────────────────────────────────────────────╯
  gemma-4-e4b · 承認する · 道具 8種 · 文脈 23%   /help
```

- 画面全体は占有しない（代替画面を使わない）。終わったやり取りはターミナルの履歴として残り、遡って読める。
- 書き換わるのは下の部分（生成中の表示・承認・入力欄・状態の行）だけ。
- モデルの応答は、届いた順に流す。Markdown の装飾はしない（まず素の文字で出す）。
- 思考（reasoning）は出さず、文字数だけを応答の後に出す（`chat` と同じ）。
- 状態の行の「文脈」は、圧縮を始める量に対する今の量の割合。概算のときは `~` を付ける。

### 色（暫定）

差し色は**緑寄りの黄緑**1色。枠、入力の記号（`›`）、選択中の項目に使う。
端末の背景が白でも黒でも読めるよう、中くらいの明るさにする（`#6BAF5A`）。
失敗・削除行は赤、警告は黄、補助の文字は端末の淡色（dim）。**色だけで意味を示さない**
（✓ / ✗ / ! の記号を必ず付ける）。`--no-color` と `NO_COLOR` では色を付けない。

## 操作

| キー | 動き |
|---|---|
| Enter | 送信 |
| Shift+Enter | 改行。端末がキーを区別して送れる場合（kitty キーボード方式に対応した kitty・WezTerm・Ghostty など） |
| Option+Enter / Ctrl+J | 改行。Shift+Enter を区別できない端末（macOS 標準のターミナルなど）でも使える代わり |
| ← → / Ctrl+A / Ctrl+E | カーソル移動 / 行頭 / 行末 |
| ↑ ↓ | 入力の履歴（カーソルが先頭行・最終行にあるとき）。それ以外は行の移動 |
| Esc | 生成・実行を止める。承認の表示中は「拒否」と同じ |
| Ctrl+C | 生成中なら止める。入力があれば消す。空なら「もう一度で終了」と出し、2回目で終了 |
| Ctrl+D | 入力が空なら終了 |
| Shift+Tab | 権限を 承認する → 編集は自動 → すべて自動 → 承認する と切り替える |
| Tab | `/` コマンドの補完 |

貼り付けは改行を含めてそのまま入力欄に入る（送信はしない）。

日本語の変換入力（IME）は、変換中の文字を入力欄のカーソル位置に出せるよう、
カーソルの位置を端末へ伝える。どこまで効くかは端末次第で、実機で確かめる。

## `/` コマンド

| コマンド | 動き |
|---|---|
| `/help` | 操作とコマンドの一覧 |
| `/new` | 新しい会話を始める。前の会話は消さずに残る |
| `/model [ID]` | ID なしで、接続先のモデル一覧。ID でそのモデルへ切り替える（道具の渡し方を判定し直す） |
| `/permission [ask\|auto-edit\|full]` | 権限を変える。引数なしで今の値 |
| `/tools [all\|read-only\|off]` | 渡す道具の範囲を変える。引数なしで今の値 |
| `/context` | 文脈の量と、圧縮を始める量 |
| `/digest` | 圧縮版を見る（`akari digest` と同じ中身） |
| `/diff` | 直前の実行が変えた内容（`akari diff` と同じ） |
| `/undo` | 直前の実行の変更を戻す。戻す前にファイルの一覧を出して確かめる |
| `/exit` | 終了（`/quit` も同じ） |

知らないコマンドは送らずに「知らないコマンドです」と出す（モデルへ `/…` を送らない）。

## 承認

05-agent.md の承認と同じ判断を、画面の中で出す。

```
╭ 承認が必要です ──────────────────────────────────╮
│ README.md を書き換えます                          │
│ - 古い行                                          │
│ + 新しい行                                        │
│ › 許可する (y)                                    │
│   以後このファイルは許可 (a)                      │
│   拒否する (n)                                    │
│   実行を止める (q)                                │
╰──────────────────────────────────────────────────╯
```

- ↑↓ と Enter で選ぶか、括弧の中のキーを押す。
- 拒否を選ぶと、理由を1行入れられる（空でよい）。理由はモデルへ伝わる。
- 差分は最大40行。超えた分は行数だけ出す。

## 終わり方

- 1回の実行の終わりには、`run` と同じ終わり方の行（完了・中断・ステップ上限…と所要時間）と、
  変更したファイルを出す。
- 画面を閉じるときは、続きの始め方（`akari -c`）と会話 ID を出す。
- 画面の中で起きたエラーで画面ごと落とさない。その実行を失敗として出し、入力欄に戻る。
  起動前の失敗（接続先が無い、到達できない）は、`run` と同じ文言と終了コードで終わる。

## 最初の版に入れないもの

- 会話の一覧から選んで続ける画面（`-c` / `--conversation` で代わりにする）
- `@ファイル名` での添付、画像
- Markdown の装飾、マウス操作
- 応答の途中での送信の予約（生成中の入力は、止めるか終わるまで送れない）
