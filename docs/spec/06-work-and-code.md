# 06 — Work 機能と Code 機能

Work と Code は、`05-agent.md` のエンジンを共有する。分ける理由は**対象と見せ方が違う**こと。

| | Work | Code |
|---|---|---|
| 対象 | 目的単位の作業。資料・文書・調査が中心 | リポジトリ。ソースの編集が中心 |
| 作業フォルダ | 任意（無くてもよい） | 必須 |
| 主役の表示 | ステップのタイムライン | ファイルツリーと差分 |
| git連携 | なし | あり（差分、ブランチ表示） |
| 既定の許可 | `ask` | `ask` |

同じエンジンなので、Work の実行中にコードを編集することもできる。禁じない。
分けているのは既定と画面であって、能力ではない。

---

## Work：プロジェクト

### データ

```ts
type Project = {
  schemaVersion: 1;
  id: string;
  name: string;
  description: string;
  instructions: string;          // このプロジェクト専用のシステムプロンプト
  workspace: string | null;      // 作業フォルダの絶対パス
  defaults: {
    endpointId?: string;
    model?: string;
    temperature?: number;
    permissionMode?: PermissionMode;
  };
  attachments: Attachment[];     // 資料
  createdAt: string; updatedAt: string;
};

type Attachment = {
  id: string;
  name: string;
  kind: "text" | "image" | "link";
  storedPath?: string;   // projects/<id>/files/ 内の相対パス
  url?: string;          // kind:"link"
  bytes: number;
  addedAt: string;
  includeByDefault: boolean;   // 会話の文脈へ自動で入れるか
};
```

- 資料はプロジェクトのディレクトリへ**コピー**する。元ファイルを消しても壊れない。
- `includeByDefault` が真の資料は、そのプロジェクトの会話の文脈へ自動で入る。
  入っている資料と合計サイズを、入力欄の上に常時表示する。
  **何が送られているか分からない状態を作らない。**
- 合計が 128KB を超える場合は、超えた分を自動で外し、外したものを名指しで表示する。

┌──────────────┬────────────────────────────────────┐

### エージェント実行の画面

「エージェントで実行」を押すと、目的を1つ書く欄が出る。実行中は次を時系列で見せる。

```
┌ 実行中  ステップ 3 / 25   [停止]  権限: 承認する ─────┐
│                                                        │
│ ▸ 1  考えた内容（折りたたみ、既定で閉じる）             │
│ ▾ 2  read_file  src/main.ts                    ✓ 完了 │
│      124行を読んだ                                     │
│ ▾ 3  edit_file  src/main.ts                  ⏸ 承認待ち│
│      ┌ 差分 ───────────────────────────────┐          │
│      │ - const x = 1;                       │          │
│      │ + const x = 2;                       │          │
│      └──────────────────────────────────────┘          │
│      [許可] [このファイルは以後許可] [拒否して理由を書く]│
└────────────────────────────────────────────────────────┘
```

- 承認待ちの間、進行表示は「待機中」に変わる。動いているように見せない。
- 完了後、下部に「この実行で変更したファイル (3)」の一覧と `[すべて元に戻す]` を出す。
- 「元に戻す」は結果（戻した / 戻せなかった）を必ず一覧で見せる。

## Code

### 画面

3ペイン。左=ファイルツリー、中央=会話/実行、右=差分またはファイル表示。
右ペインは折りたためる。

```
┌─────────────┬───────────────────────┬──────────────────┐
│ 📁 my-repo   │  会話 / 実行の流れ     │ 差分: src/a.ts   │
│  main ●3     │                       │                  │
│ ▾ src        │  > テストを直して      │  12  - foo()     │
│    a.ts  M   │                       │  12  + bar()     │
│    b.ts      │  ▾ run_command        │                  │
│ ▾ tests      │    npm test           │ [適用] [却下]    │
│    a.test.ts │    ⏸ 承認待ち          │                  │
│              │    [許可][許可(npm)]  │                  │
│ [変更 3件]   │    [拒否]             │                  │
└─────────────┴───────────────────────┴──────────────────┘
```

### git 連携

git は**読み取りにしか使わない**。Akari が勝手にコミット・ブランチ操作・stash をすることはない。

- 現在のブランチ名と、変更ファイル数をツリー上部に出す。
- ファイル名の横に `M`（変更）/ `A`（追加）/ `?`（未追跡）を出す。
- 「変更 N件」を押すと、`git diff` 相当（作業ツリー vs HEAD）を右ペインに出す。
- git リポジトリでない場合、この行は出さない。エラーにもしない。
- コミットしたい場合は、利用者が `run_command` の承認を通して行う。
  つまり `git commit` は**必ず承認を経る**。`agent.deniedCommands` に
  `git push --force` と `git reset --hard` を既定で入れる。

### ファイル参照の補完

入力欄で `@` を打つと、作業フォルダ内のファイルを絞り込んで挿入できる。
挿入されたものは、送信時に中身が読まれて文脈へ入る。
入力欄の下に「添付されるファイル: 2件 / 8KB」と出す。

### 差分の適用

モデルがコードブロックだけを返し、ツールを使わなかった場合でも作業を進められるようにする。

- コードブロックの情報文字列にファイルパスがある場合（```` ```ts src/a.ts ````）、
  `[このファイルへ適用]` ボタンを出す。
- 押すと差分プレビューを出し、確認後に書き込む。この書き込みも変更記録に入り、取り消せる。
- パスが無いコードブロックには、このボタンを出さない（どこへ書くか推測しない）。

## Work と Code の共通の制約

- 作業フォルダが未設定のときにエージェント実行を押したら、
  「作業フォルダを選んでください」と選択ダイアログを出す。ツールなしで実行しない。
- 作業フォルダがホームディレクトリそのもの、`/`、`C:\`、Akari のデータディレクトリの場合は
  拒否する。範囲が広すぎて取り消しが現実的でないため。
- 実行前に、作業フォルダのパスと権限モードを1行で表示する。何に対して何をするかを、
  実行開始前に必ず読める状態にする。
