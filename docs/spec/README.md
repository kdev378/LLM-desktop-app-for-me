# Akari 仕様書

**Akari（灯り）** — LLMにコードを書かせるためのハーネス。
デスクトップアプリ、CLI、外部ツール向けAPI（HTTP + MCP）の3つの使い口を持つ。

実装より仕様が先。実装中に仕様と違う判断をしたら、**コードより先にここを直す**。
ここに書いていない機能を実装しない。

## 決まっていることの要点

読むのが1つだけなら、ここ。

- **中核は1つ**。`@akari/core` にモデル往復・ツール・保存を寄せ、デスクトップ・CLI・APIは
  見せ方だけを持つ。「同じはず」ではなく「同じコードを通る」。
- **Akari は1エージェント分の手足**。エージェント同士の会話、司会、mergeの判断は
  外部のマルチエージェントツールの仕事であって、Akari の仕事ではない。
- **拡張の口はMCPだけ**。独自のプラグイン機構を作らない。
- **ハーネスAPIは localhost 限定＋トークン**。ファイル編集とコマンド実行を開ける口だから。
- **Webは既定で無効**。有効にしても、名前解決後のIPを検査して内部ネットワークへ出さない。
- **エージェントの結果はイベントの流れ**。画面もターミナルも `--json` も、
  同じイベント列から作る。
- **作業フォルダの外は触れない**。シンボリックリンクを解決した実体パスで検査し、
  外れたら承認画面すら出さずに拒否する。
- **ファイル変更は必ず記録してから行う**。バックアップと変更記録があるので、
  実行単位で取り消せる。取り消せなかったものは名指しで報告する。
- **保存はJSONファイル**。DBを使わない。破綻する条件（会話5000件）を先に決めてある。
- **鍵は平文で保存される**。OSのファイル権限に依存した保護であり、暗号化ではない。
  この制限は設定画面にも書く。
- **待機中に外部へ通信しない**。テレメトリも更新確認も入れない。
