# 00 — 概要・目的・完成条件

## これは何か

**Akari（灯り）** は、LLMにコードを書かせるための**ハーネス**である。
ハーネスとは、モデルと道具と安全装置をひとまとめにして、
「目的を渡すと手が動く」状態を作る土台のこと。Claude Code や Codex がやっていることの、
手元版だと思えばよい。

その土台の上に、次の3つの使い口を持つ。

| 使い口 | 誰が使うか |
|---|---|
| **デスクトップアプリ** | 人。会話・作業・コード編集を画面で |
| **CLI** | 人。ターミナルから |
| **ハーネスAPI（ローカルHTTP + MCP）** | 他のプログラム。複数エージェントを束ねる外部ツールから |

- **対象の利用者**: オーナー1人。ただし3つ目の使い口は、オーナーが別に作る
  マルチエージェント自動開発ツールが利用者になる。
- **解決する問題**:
  1. ローカルLLMサーバ（Ollama / llama.cpp / LM Studio / vLLM 等）を立てても、
     実際に使う入口が `curl` か素朴なWeb UIしかない。
  2. Claude Code や Codex に相当するものが、ローカルLLM向けには手元に無い。
  3. 複数のエージェントをチャット上（Discord等）で会話させ、成果物をGitでまとめる仕組みを作るとき、
     各エージェントの「実際に手を動かす部分」を担う共通の土台が要る。
- **やること**: OpenAI互換APIを話す相手なら何にでも繋がる1つの中核で、
  「会話する」「作業をまとめる」「エージェントに手を動かさせる」「コードを書かせる」を扱い、
  それを画面・ターミナル・API の3方向へ同じ形で出す。

## 外部のマルチエージェントツールとの関係

オーナーは別に、チャットサービス上で複数のエージェントを会話させ、
成果物を権限を持つエージェントがGitでmergeする自動開発ツールを作る予定。
**Akari はその「1エージェント分の手足」**にあたる。

```
[チャット上の会話・指示]           ← 外部ツールの担当
        │
        ├─ エージェントA ──→ Akari インスタンス1 ──→ ローカルLLM / API
        ├─ エージェントB ──→ Akari インスタンス2 ──→ ローカルLLM / API
        └─ 統合役(権限あり) ─→ git merge          ← 外部ツールの担当
```

Akari が持つ責任は「1つの目的を受けて、作業フォルダの中で手を動かし、
何をしたかを構造化して返す」ところまで。
**会話の司会、エージェント間の調整、mergeの判断は Akari の仕事ではない**（非目標）。

そのために Akari 側が用意するもの:

- **ハーネスAPI**（`12-harness-api.md`）— 実行の作成、イベントの購読、承認の返答、停止、取り消し。
- **作業の隔離** — 実行ごとに git worktree を切れる。エージェント同士が同じファイルを踏まない。
- **チャットへ貼れる形** — イベント列に加えて、Markdownの経過テキストを取り出せる。
- **相関のためのラベル** — 実行に任意のラベル（チャンネルIDやエージェント名）を付けて引ける。

## 非目標（作らないもの）

明示的に作らない。これを作りたくなったら、まず仕様を更新して承認を取る。

- モデルのダウンロード・量子化・サーバ起動の管理。Ollama 等に任せ、Akari は接続するだけ。
- 独自の推論エンジン。llama.cpp 等を直接組み込まない。
- **エージェント同士の会話・司会・役割分担**。外部ツールの担当。Akari は1実行を回すだけ。
- **git の merge 判断、PRの作成、レビューの承認**。Akari は worktree を用意し差分を報告するところまで。
- **チャットサービスへの接続そのもの**（Discord等のボット実装）。外部ツールの担当。
- マルチユーザー、アカウント、クラウド同期、チーム共有。認証は「同じPCの持ち主かどうか」まで。
- テーマストア、UI拡張。
- モバイル対応、Web版、ブラウザ拡張。
- 音声入出力。
- 自前の埋め込みモデル・検索エンジンの実装。埋め込みは接続先の `/embeddings`、
  Web検索は外部の検索APIに任せる。

### 以前は非目標だったが、方針を変えたもの

| 項目 | 変更 | 理由 |
|---|---|---|
| RAG基盤（ベクトル索引） | **入れる**（`14-memory.md`） | 文脈長の小さいローカルLLMでは、必要な部分だけ渡す仕組みが無いとコードを書かせられない |
| 文脈の圧縮 | **入れる**（`16-context.md`） | 文脈長の小さいモデルでは、圧縮が無いと数ステップで作業が止まる。古い分を黙って捨てると、決めたことと棄却したことを忘れて同じ失敗を繰り返す |
| MCP | **入れる**（`13-mcp.md`）。使う側と、なる側の両方 | 道具を毎回自作しない。既存のMCPサーバ群を使い、Akariの安全な道具も外へ出す |
| プラグイン機構 | MCP に置き換える | 独自の拡張機構は作らない。外への口はMCPひとつにする |

## 完成条件

外から見て確かめられる形で書く。すべて満たしたときに v1 完成とする。

### 接続
- [ ] 設定画面でベースURL（例 `http://localhost:11434/v1`）を入れると、`/models` から取得したモデル一覧が出る。
- [ ] 接続できないとき、原因（到達不可 / 認証 / 応答が非互換）が区別して表示され、対処が書いてある。
- [ ] 接続先を複数登録し、切り替えられる。

### Chat
- [ ] 新しい会話を作り、送信すると応答がトークン単位で流れて表示される。
- [ ] 生成中に停止でき、そこまでの内容が会話に残る。
- [ ] アプリを再起動しても、会話一覧と各会話の内容が残っている。
- [ ] 自分の発言を編集して再送すると、以降が作り直され、元の枝も辿れる。
- [ ] コードブロックがハイライトされ、1クリックでコピーできる。

### Work（プロジェクト）
- [ ] プロジェクトを作り、専用の指示・既定モデル・作業フォルダ・資料ファイルを設定できる。
- [ ] プロジェクト内で始めた会話は、その設定を引き継いだ状態で始まる。
- [ ] プロジェクトに属する会話が、そのプロジェクトの画面に一覧される。

### Work（エージェント実行）
- [ ] 目的を1つ書いて実行すると、ツールを使いながら複数ステップ進み、各ステップが時系列で見える。
- [ ] ファイル書き込みとコマンド実行の前に承認を求め、拒否すると実行されない。
- [ ] 作業フォルダの外を読み書きしようとした場合は、承認以前に拒否される。
- [ ] 実行後に「元に戻す」で、その実行が行ったファイル変更を戻せる。
- [ ] 実行中に停止でき、停止時点までの変更と経過が残る。

### Code
- [ ] 作業ディレクトリを開くと、ファイルツリーと、その中身をエージェントが読める状態になる。
- [ ] 提案された変更が before/after の差分として見え、適用・却下を選べる。
- [ ] コマンド実行の出力（標準出力・標準エラー・終了コード）が読める形で残る。
- [ ] git リポジトリなら、変更後に `git diff` 相当の差分が画面から確認できる。

### 記憶（ベクトル索引）
- [ ] 作業フォルダに索引を作ると、「どこで◯◯を定義しているか」に対して該当ファイルと行が返る。
- [ ] 索引を作ったときと違う埋め込みモデルで検索しようとすると、混ぜずに拒否される。
- [ ] ファイルを変更して索引を更新すると、変わったファイルだけが作り直される。

### MCP
- [ ] 外部のMCPサーバを登録すると、そのツールがエージェントから使える。
- [ ] MCPのツールも、Akari自身のツールと同じ承認とログを通る。
- [ ] `akari mcp serve` で、Akari のツール（取り消し可能なファイル編集を含む）を他のツールから使える。

### Web
- [ ] `web_search` で検索結果（題・URL・抜粋）が返る。
- [ ] `web_fetch` でページ本文がテキストで返る。
- [ ] `localhost` やクラウドのメタデータへの `web_fetch` は拒否される。
- [ ] 外部へ問い合わせる前に、何が送られるかが分かる。

### 文脈の圧縮
- [ ] 文脈が閾値を超えると、古いターンが自動で圧縮され、そのことが画面に出る。
- [ ] 圧縮版は「決定・確認済み・棄却案・未解決・次の行動」の5分類で読める。
- [ ] 圧縮しても、生のメッセージが会話ファイルから消えていない。
- [ ] 圧縮された部分を検索して、原文を取り出せる。
- [ ] 圧縮に失敗したときは、そうと分かる形で表示され、機械的な要約へ落ちる。

### ハーネスAPI
- [ ] `akari serve` を起動し、HTTPで実行を作れる。
- [ ] 実行のイベントをSSEで購読でき、途中で切れても続きから読み直せる。
- [ ] 承認の要求がHTTPに出て、HTTPで許可・拒否を返せる。
- [ ] トークンなしのリクエストは拒否される。
- [ ] 実行にラベルを付けて、あとからラベルで引ける。
- [ ] 実行を独立した git worktree で走らせ、ブランチ名を受け取れる。
- [ ] 経過をチャットに貼れるMarkdownとして取り出せる。

### CLI
- [ ] `akari "このリポジトリのテストを通して"` をリポジトリ直下で実行すると、デスクトップ版と同じ挙動でエージェントが動く。
- [ ] `akari chat` でツールなしの対話ができる。
- [ ] `akari --json` で1行1イベントの機械可読な出力が得られる。
- [ ] `akari undo` で直前の実行のファイル変更が戻る。
- [ ] `akari doctor` が接続先・モデル・機能対応状況・設定の要約を出す。

### 運用
- [ ] Windows / macOS / Linux でインストーラまたは実行可能な配布物ができる。
- [ ] 「問題報告用の書き出し」1コマンドで、バージョン・設定要約（秘密は伏せる）・直近のログがまとまったファイルが出る。
- [ ] 保存データの場所と形式がドキュメントに書かれており、手で読める。

## 用語

| 語 | 意味 |
|---|---|
| **接続先（Endpoint）** | OpenAI互換APIを話すサーバ1つ分の設定。ベースURL、鍵、既定モデル、対応機能。 |
| **会話（Conversation）** | メッセージの列。1つのファイルに保存される。 |
| **プロジェクト（Project）** | 作業単位。専用指示・既定設定・作業フォルダ・資料・会話をまとめる。 |
| **実行（Run）** | エージェントが目的を受けて、停止または完了するまで回る1回分。 |
| **ステップ（Step）** | 1回のモデル呼び出しと、それに続くツール実行。 |
| **ツール（Tool）** | モデルが呼べる関数。ファイル読み書き、検索、コマンド実行など。 |
| **作業フォルダ（Workspace）** | ツールが触ってよい唯一の範囲。この外は拒否される。 |
| **変更記録（Change Journal）** | 実行がファイルへ行った変更の記録。差分表示と取り消しの根拠。 |
